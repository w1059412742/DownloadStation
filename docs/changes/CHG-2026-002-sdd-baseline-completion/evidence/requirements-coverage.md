## 原始资料特殊处置

- PRD 的访客、版本、下载、后台、看板、NAS 扫描、绑定、哈希、删除和 SOP 均分别进入 CAT/DST/ADM/OPS 的 REQ；没有用一条“CRUD 已完成”替代细节。
- UIUX 的设计系统、导航、响应式、主题、正文代码复制、详情版本折叠、后台扫描抽屉、登录和过渡交互进入 CAT/ADM 的独立 REQ；精确像素值未被擅自写成业务验收，保留为视觉参考或可测试的响应式/交互行为。
- 当前代码中已经存在但旧 PRD 未完整描述的分享 `/s/:id`、免责声明、后台预览、拖拽上传和上传进度也进入相应 REQ，避免“历史文档没有所以不调查”。
- 当前模型/DTO/接口存在但用户流程未闭合的截图、扫描一键绑定、Top10 和空间统计均写成目标与明确当前差距，不把接口存在当成完成。
- 单平台、多平台；Tiptap HTML、Markdown；JWT、Cookie；单容器、分离容器等冲突集中写入 Spec 的基线决策和 Change，不能在不同文件隐式使用两个结论。

开发前从 REQ → AC → Change 任务开始；测试证据挂在任务和 AC 下。发现来源条款没有去向时先更新本文件和对应 Spec，再分配实现。发现当前代码与 approved Spec 不一致时建立 fix/feature/config Change，保留本表的来源和证据，不降低目标。

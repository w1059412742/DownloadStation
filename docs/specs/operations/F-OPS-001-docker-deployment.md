## 目标与范围

定义可重复镜像、单容器拓扑、前后端同源路由、持久卷、秘密、日志、迁移、健康检查、备份、恢复、回滚和发布证据。前后端分离 Docker 输入仅作为开发/实验参考，不得被当作已验证生产路径。

## 基线决策与证据

本 Spec 采用“代码优先的正式现状基线”。用户已明确确认：本阶段未单独确认的行为，以当前代码、当前前端消费者、数据模型、Docker 输入和发布脚本实际表达的行为为准。该确认包括当前实现中已经存在的限制和缺陷；它们不会被伪装成已修复功能。

本文件中的 REQ/AC 用于记录本能力的稳定边界和可追溯验收口径；与当前实现存在差异的历史目标，按下方“已知问题备注”处理，暂不作为本阶段已完成能力。后续要改变行为，必须建立新的 Change，更新 REQ/AC、契约、消费者和验证证据。

## 规范性需求（当前正式基线）

### REQ-OPS-001-001
当发布人员以固定源码提交和版本号构建群晖镜像时，构建必须在一个可运行镜像中包含前端静态资源、ASP.NET Core API 和历史路由回退，镜像标签必须包含不可变版本号。
来源：用户明确 Docker 发布；Dockerfile.Synology

### REQ-OPS-001-002
生产单容器必须把 SQLite 数据库、上传资源、日志和软件包分别映射到宿主机持久卷；容器重建后数据库记录、图片、日志和软件文件仍可读取。
来源：Dockerfile.Synology、docker-compose.synology.yml

### REQ-OPS-001-003
生产启动必须通过环境变量或受保护部署文件注入连接字符串、JWT 密钥、管理员密码、上传根目录、软件根目录和日志路径；镜像与公开 compose 示例不得包含可用生产秘密。
来源：Program.cs、appsettings、compose；安全基线

### REQ-OPS-001-004
每次发布必须保存源码提交、镜像版本标签、镜像摘要、构建时间、构建命令、配置样例和验证结果；latest 只能作为指向已验证版本的便利标签。
来源：发布流程的追溯要求

### REQ-OPS-001-005
当正式单容器启动时，系统必须提供不写业务数据的健康检查入口或等价探测；健康检查失败时发布流程不得标记成功。
来源：现有无健康检查；发布门禁要求

### REQ-OPS-001-006
当 EF Core 迁移失败时，应用必须记录可诊断错误并以非成功启动状态退出或阻止业务请求，不得继续提供看似正常的空数据库服务。
来源：Program.cs:125–134；迁移安全边界

### REQ-OPS-001-007
发布前必须备份 SQLite 数据库并与同一版本的上传资源、软件包、环境配置和 compose 记录建立恢复集合；恢复演练必须在隔离卷验证版本、数据和文件的对应关系。
来源：恢复边界；用户要求 Docker 发布

### REQ-OPS-001-008
应用日志必须写入持久目录并包含启动、迁移、认证拒绝、文件处理和后台哈希的结构化可诊断记录；默认日志不得写入密码、JWT、完整物理路径给公开响应或文件内容。
来源：Serilog、Program.cs、公共契约

### REQ-OPS-001-009
容器运行用户、宿主机卷权限和上传/软件根目录必须满足最小可写范围；应用无法写入所需目录时必须报告明确错误，不静默写入容器临时目录。
来源：群晖卷与 ASP.NET 文件写入

### REQ-OPS-001-010
发布脚本必须在执行前校验版本、镜像名、仓库和 Docker 登录状态，禁止自动丢弃未提交工作区或未经确认的 git pull/reset；shell 和 PowerShell 使用明确变量边界并在失败时停止。
来源：publish.ps1、publish.sh 当前风险

### REQ-OPS-001-011
Docker 构建必须使用锁文件可重复安装前端依赖，隔离 node_modules、dist、bin、obj、数据库、上传和日志；构建上下文不把运行时数据复制进镜像。
来源：Dockerfile*；当前无 .dockerignore

### REQ-OPS-001-012
正式拓扑采用群晖单容器作为唯一发布标准；前后端分离文件仅保留为开发/实验参考，除非另有独立 Change 明确代理、CORS、上传卷和健康检查。
来源：当前单容器可合一；分离 Dockerfile.Web 无 proxy_pass

### REQ-OPS-001-013
单容器必须在同一 origin 提供 `/`、`/api`、`/uploads` 和 Vue history fallback；刷新公开/管理深链接时不返回 Nginx 或 API 404。
来源：Program.cs 静态文件与 fallback

### REQ-OPS-001-014
当镜像、配置或迁移验证失败时，发布流程必须保留上一已验证版本和备份，可回滚镜像与配置；回滚结果须再次执行健康检查和关键 API 探测。
来源：发布与恢复边界

### REQ-OPS-001-015
发布验证至少覆盖匿名列表、公开详情、可见版本列表、范围下载、管理员登录、后台统计、上传/扫描链路和重建卷；未执行的项目必须明确标为未验证，不得写成发布完成。
来源：Docker 验收门禁

### REQ-OPS-001-016
发布记录必须注明时区、镜像标签/摘要、宿主卷、环境变量来源、迁移结果、健康检查、回滚结果和负责人确认；文档状态 verified 不等于镜像已经推送或 NAS 已上线。
来源：SDD 状态边界

## 质量与边界

构建、启动、健康、关键 API、持久卷重建和恢复均需实际证据；Dockerfile/compose 静态存在不代表发布成功。安全秘密、数据库备份和软件包必须作为同一恢复集合管理。

## 各端和契约关系

接口和 DTO 的当前入口见 [HTTP 契约参考](../../contracts/http-api.md)。后端控制器、请求/响应 DTO、EF 模型和迁移是当前实现事实的权威来源；本 Spec 的 REQ/AC 是目标行为来源。涉及跨端的需求必须同时核对 API、消费者、持久化和错误处理。

## 必要技术说明

正式路径使用 `Dockerfile.Synology` 的前端构建、后端发布和单容器静态托管；`/app/data` 持久化 SQLite、uploads、logs，`/data/software` 持久化软件包。`Program.cs` 的迁移失败、静态资源和 history fallback 必须纳入启动探测。发布脚本不允许未经确认的 reset/pull。

## 验收场景

### AC-OPS-001-001（验证 REQ-OPS-001-001）
Given 固定提交、版本标签和可用 Docker 引擎
When 构建并启动镜像
Then 前端首页、API 和管理登录入口从同一端口可访问，镜像标签包含版本号且不依赖 latest

### AC-OPS-001-002（验证 REQ-OPS-001-002）
Given 临时宿主机 data/software_repo 含测试数据库、图片、日志和软件包
When 删除并重建容器
Then 四类数据仍能通过应用或文件检查读取，卷路径没有落到容器临时层

### AC-OPS-001-003（验证 REQ-OPS-001-003）
Given 环境提供随机 JWT/管理员密码，镜像不含生产值
When 启动并登录，再检查镜像/日志
Then 应用使用注入值；错误配置拒绝启动或明确失败；日志和仓库不输出秘密

### AC-OPS-001-004（验证 REQ-OPS-001-004）
Given 固定提交和已构建镜像
When 填写发布记录并更新 latest
Then 记录可由提交和镜像元数据互相核对；latest 指向同一已验证版本

### AC-OPS-001-005（验证 REQ-OPS-001-005）
Given 数据库与卷配置正确及错误两种容器
When 执行健康探测
Then 正确配置返回健康结果；错误配置失败，发布记录为未通过且不推送 latest

### AC-OPS-001-006（验证 REQ-OPS-001-006）
Given 只读/损坏数据库或不兼容迁移
When 启动容器
Then 迁移失败可从日志和退出状态识别，业务入口不可误报正常

### AC-OPS-001-007（验证 REQ-OPS-001-007）
Given 一份带图片和软件包的备份集合及对应镜像标签
When 恢复到空卷并启动
Then 公开详情、图片和下载内容均恢复，迁移历史与镜像版本可核对；仅恢复数据库不得标记完整恢复

### AC-OPS-001-008（验证 REQ-OPS-001-008）
Given 执行成功/失败登录、哈希和迁移案例
When 查看持久日志与公开响应
Then 有对应事件和错误关联 ID；没有秘密、文件内容或不必要的公开路径

### AC-OPS-001-009（验证 REQ-OPS-001-009）
Given 分别给予正确和只读卷权限
When 上传图片、绑定文件、写日志
Then 正确权限成功并落在卷；只读权限产生可诊断失败，数据不落到临时层

### AC-OPS-001-010（验证 REQ-OPS-001-010）
Given 未提交工作区、缺版本或未登录仓库
When 执行发布前检查
Then 脚本拒绝不安全条件并保留工作区；有效条件下变量正确展开，任一构建/推送失败终止

### AC-OPS-001-011（验证 REQ-OPS-001-011）
Given 同一提交和锁文件执行两次干净构建
When 比较镜像构建输入与结果
Then 依赖版本来自锁文件，运行时数据不进入镜像，二次构建不会读取本地 node_modules/运行数据

### AC-OPS-001-012（验证 REQ-OPS-001-012）
Given 仓库同时存在两套 Docker 输入
When 按正式发布文档执行部署
Then 发布记录只引用单容器；分离文件不能被当作已验证生产路径

### AC-OPS-001-013（验证 REQ-OPS-001-013）
Given 构建镜像后访问首页、详情、管理登录、API 和上传资源
When 直接请求深链接和资源
Then 所有路径由同一端口按用途返回正确内容，刷新不丢失路由

### AC-OPS-001-014（验证 REQ-OPS-001-014）
Given 已有版本 V1，新版本 V2 启动/迁移失败
When 回滚到 V1
Then V1 可启动且数据/文件可读，健康和关键 API 通过，记录包含失败和回滚证据

### AC-OPS-001-015（验证 REQ-OPS-001-015）
Given 固定镜像、临时卷和测试数据
When 执行最小发布清单
Then 清单每项有实际命令/响应/结果；未执行项保持未验证，不能生成完成状态

### AC-OPS-001-016（验证 REQ-OPS-001-016）
Given 仅完成本地构建、已推送镜像和已上线 NAS 三种情形
When 分别更新记录
Then 每种状态只在对应证据存在时标记，文档验证不冒充生产部署

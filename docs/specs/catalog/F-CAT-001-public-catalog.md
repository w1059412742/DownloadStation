## 目标与范围

定义匿名访客如何发现、筛选、阅读、分享和下载已发布软件。包含分类树、平台、搜索、排序、详情正文、截图相册、版本展示、哈希、更新日志、分享、响应式和主题交互；管理写入和物理文件生命周期分别由 F-ADM-001、F-DST-001 负责。

## 基线决策与证据

本 Spec 采用“代码优先的正式现状基线”。用户已明确确认：本阶段未单独确认的行为，以当前代码、当前前端消费者、数据模型、Docker 输入和发布脚本实际表达的行为为准。该确认包括当前实现中已经存在的限制和缺陷；它们不会被伪装成已修复功能。

本文件中的 REQ/AC 用于记录本能力的稳定边界和可追溯验收口径；与当前实现存在差异的历史目标，按下方“已知问题备注”处理，暂不作为本阶段已完成能力。后续要改变行为，必须建立新的 Change，更新 REQ/AC、契约、消费者和验证证据。

## 规范性需求（当前正式基线）

### REQ-CAT-001-001
当匿名访客请求软件列表时，系统必须只返回 Published 软件的名称、简介、图标、分类、平台和累计下载量，不返回 Draft 软件。
来源：PRD:8、18、43；公开 SoftwaresController / SoftwareService

### REQ-CAT-001-002
当访客提交搜索词时，系统必须先去除首尾空白，再按名称或简介包含该字面子串进行匹配；空词不增加搜索限制，其他过滤条件仍共同生效。
来源：PRD:17；Home.vue / SoftwareService.GetPagedListAsync

### REQ-CAT-001-003
当访客选择分类节点时，系统必须筛选该节点及全部后代节点；导航必须能到达任意深度，可用相邻两层导航和路径回退呈现，不限制数据树深度。
来源：PRD:13；UIUX:5、43–45；分类树与后代查询

### REQ-CAT-001-004
当访客选择平台时，系统必须返回 PlatformId 等于该平台且已发布的软件；未选择平台时不增加平台限制。当前正式基线采用软件单平台关系。
来源：PRD:15、41；当前单平台模型；本次取舍 D1

### REQ-CAT-001-005
当访客选择 popular 时，系统必须按 TotalDownloads 降序排序；选择 latest 或 API 未指定排序时按 UpdatedAt 降序排序；同值按 Id 升序稳定排列。首页初次进入采用 popular。
来源：PRD:16；Home 默认与 API 默认分别记录；本次取舍 D4

### REQ-CAT-001-006
当访客打开软件详情时，系统必须返回已发布软件的基础信息、正文、官网、分类、平台、截图引用和累计下载量；空的可选字段不显示失效控件，不存在或 Draft 软件返回 404。
来源：PRD:20；公开详情 API / SoftwareDetail.vue

### REQ-CAT-001-007
当访客请求公开版本列表时，系统必须先确认父软件为 Published，仅返回其可见版本，并从公开响应中排除 FilePath；不存在或 Draft 父软件返回 404。
来源：PRD:43；本次静态差距 R01

### REQ-CAT-001-008
当列表请求的页码或页大小非法时，系统必须拒绝请求而不执行无界查询；有效范围为 page≥1、1≤pageSize≤100，超出末页返回空 items，total 为过滤后的软件数。
来源：当前分页接口；校验与稳定结果为本次技术建议

### REQ-CAT-001-009
当公开列表加载、为空或请求失败时，页面必须分别显示加载状态、空结果或可重试错误；失败不推进成功页码、不清空已成功加载的项目，变更筛选从第 1 页重新查询。
来源：Home.vue 的分页/加载消费者

### REQ-CAT-001-010
当展示软件正文时，系统必须渲染现有 Tiptap HTML 内容和图片，保留支持的标题、列表、引用、代码和强调格式，同时阻止 script、事件属性和 javascript: 等可执行 URL；存量 HTML 不自动转换为 Markdown。
来源：PRD Markdown 与 RichEditor.getHTML 冲突；取舍 D2

### REQ-CAT-001-011
当软件配置截图相册时，页面必须按截图 SortOrder 升序、同序按 Id 升序展示图片；点击打开灯箱，支持前后切换和关闭，空相册不显示空图片区。
来源：PRD:22、42；当前模型/读 DTO 已有，写入与 UI 缺失

### REQ-CAT-001-012
当展示版本卡片时，系统必须采用 REQ-DST-001-017 的统一顺序，展示版本号、创建日期、文件大小、该版本下载数和哈希状态；主下载选择按 REQ-CAT-001-016，不把日期重命名为不真实的更新时间。
来源：PRD:25–26；当前 CreatedAt 字段；取舍 D4

### REQ-CAT-001-013
当版本 HashStatus 为 Done 时，页面必须允许查看和复制完整 64 位小写 SHA-256；Pending/Computing 显示计算状态，Failed 显示失败状态，不把内部错误文本当校验码，也不承诺提供 MD5。
来源：PRD:8、26、54；当前 SHA-256 作业

### REQ-CAT-001-014
当访客展开版本更新日志时，系统必须以安全 Markdown 展示该版本日志，默认收起；空日志显示无更新说明，不执行嵌入 HTML/脚本。正文 HTML 与版本日志 Markdown 分别处理。
来源：PRD:27；UIUX:87；当前 textarea/文本展示

### REQ-CAT-001-015
当公开版本超过 3 项时，页面必须初始显示统一排序的前 3 项，提供展开全部历史版本及再次收起动作；不超过 3 项时不显示多余展开按钮。
来源：PRD:28；UIUX:67

### REQ-CAT-001-016
当访客使用主下载按钮时，页面必须选择可见默认版本，无默认时选择统一顺序中的首个可见版本；没有可见版本时禁用主下载并显示无可下载版本。
来源：当前默认主下载及空版本消费者

### REQ-CAT-001-017
当用户分享软件时，页面必须生成 /s/{softwareId} 的本站链接并沿用公开访问权限；复制失败时显示可手动复制的链接和失败提示，不显示虚假的复制成功。
来源：router /s/:id；SoftwareDetail share

### REQ-CAT-001-018
当展示公开详情时，页面必须保留现有用途/版权免责声明；该声明不作为文件可见性、权限或内容合法性的程序判定条件。
来源：当前详情已有免责声明

### REQ-CAT-001-019
当访客打开官网链接时，页面必须只使用非空的 http/https 官网地址，并在新页面打开时隔离 opener；无效地址不生成可点击的危险链接。
来源：PRD:20、40；当前官网链接字段

### REQ-CAT-001-020
当访客浏览或下载公开软件时，系统必须允许匿名使用，不强制管理员登录，也不插入商业广告界面；个人 NAS 使用范围不包含会员、支付或多租户。
来源：PRD:5–9 的产品边界

### REQ-CAT-001-021
当页面在 360px、800px、1280px 宽视口展示软件大厅时，软件卡片必须分别呈现 1、2、4 列且无页面横向溢出，搜索、分类与下载入口保持可操作。
来源：UIUX:31、47；本次响应式验收样本

### REQ-CAT-001-022
当维护页面视觉时，系统必须复用现有 style.css 的颜色、字体和基础组件规则，保持层次清楚及可读文本；旧 UIUX 的精确像素、阴影和字体字重仅作为历史设计参考，不另建平行设计令牌。
来源：UIUX:1–28、31–57；取舍 D6

### REQ-CAT-001-023
当用户切换明暗主题时，页面必须同步公开页和后台的主题并在本浏览器持久化选择；首次无选择时采用系统主题，不改变业务数据。
来源：UIUX:37；当前 Header 无切换入口，保留产品目标

### REQ-CAT-001-024
当正文中存在代码块时，页面必须提供复制代码内容的动作，成功/失败分别给出真实反馈，复制值不包含展示行号或格式标签。
来源：UIUX:61

## 质量与边界

公开访问无需管理员 JWT；不存在、草稿父软件、隐藏版本和缺失物理文件不得泄露；用户可观察错误必须与成功响应区分。质量数值只有在有环境、负载和测量方式时才进入后续 Change。

## 各端和契约关系

接口和 DTO 的当前入口见 [HTTP 契约参考](../../contracts/http-api.md)。后端控制器、请求/响应 DTO、EF 模型和迁移是当前实现事实的权威来源；本 Spec 的 REQ/AC 是目标行为来源。涉及跨端的需求必须同时核对 API、消费者、持久化和错误处理。

## 必要技术说明

公开列表/详情由 `Public/SoftwaresController` 与 `SoftwareService` 提供；公开版本/下载由 `Public/DownloadController` 与 `VersionService` 提供。正文保存事实为 Tiptap HTML，版本日志目标为 Markdown；实现时必须使用安全渲染，不把依赖声明当作已调用证据。

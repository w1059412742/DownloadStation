## 目标与范围

对有效软件进行安装包上传/绑定、版本资料编辑、可见性及默认选择，并提供文件下载。本规格定义顺序操作的版本状态；计数准确性、物理删除失败/共享路径、上传跨文件与数据库回滚、并发竞争及重试去重不在本次采用范围，见B04/B05/B07。

## 功能规则

### REQ-版本管理-001-001：新增与编辑版本
成功上传或绑定有效软件的安装包后，系统必须创建版本号、普通文本日志、文件信息及创建/更新时间，初始HashStatus=Pending、IsVisible=1、IsDefault=1；必须同时清除该软件旧版本的默认标记。有效软件不存在或上传文件为空必须拒绝上传。版本资料更新只修改版本号、日志及更新时间；不存在目标返回不存在。

### REQ-版本管理-001-002：手工设置默认版本
手工设默认必须只接受可见版本；对已默认版本重复设置必须成功且保持原默认；设另一可见版本时必须清除旧默认并设置目标。隐藏版本不得成为默认。

### REQ-版本管理-001-003：显隐及删除后的默认选择
对有效0/1可见性执行切换或成功删除版本记录时，默认变化必须符合下表。每个软件最多有一个默认，默认必须可见；没有可见版本时必须没有默认。

| 事件与前提 | 版本/默认结果 |
| --- | --- |
| 隐藏当前默认 | 该版隐藏并取消默认，选创建时间最新的剩余可见版本为默认；没有则无默认 |
| 隐藏非默认 | 只隐藏目标，已有默认不变 |
| 显示版本且已有可见默认 | 只显示目标，默认不变 |
| 显示版本且没有可见默认 | 目标可见并成为默认 |
| 成功删除默认记录 | 移除目标记录，选最新剩余可见版；没有则无默认 |
| 成功删除非默认记录 | 移除目标记录，已有默认不变 |

创建时间并列时现有来源未给出额外选取规则，本范围不作固定ID顺序承诺。记录删除后的默认变化不批准物理文件异常被忽略的现状。

### REQ-版本管理-001-004：版本列表与下载选择
后台必须列出全部版本，公共查询只列可见版本，均默认版优先、再创建时间倒序。公共详情“下载最新版”必须选当前默认版，无默认时选列表首个可见版本；无版本时不得发起某个版本下载。

### REQ-版本管理-001-005：文件下载及拒绝条件
满足公开与文件库边界后，版本不存在、归属不匹配、隐藏或物理文件不存在时必须拒绝下载，当前相应契约为404；可读文件必须按安装包文件名返回二进制内容并支持有效HTTP Range请求。哈希Pending或Failed不构成当前已确认的下载阻断条件。

## 输入、处理顺序与失败边界

1. 已认证管理员在软件编辑页选择上传（文件、软件ID、版本号、可空普通文本日志）或手工绑定（库内有效路径、软件ID、版本号、日志）；后者不复制已有文件。API传输格式以DTO/Controller为准，不混用JSON绑定和multipart上传。软件和文件必须满足访问控制及软件库规格；绑定缺文件被现代码接受是B04，不把0字节入库写成目标。
2. 上传先拒绝空文件，再检查软件存在，再派生该软件的库内目录、写文件。目录使用软件名中的空格替换为下划线；同名文件存在时在扩展名前加服务端本地时间`_yyyyMMddHHmmss`。这些取名规则仅适用无穿越字符且无同秒冲突的有效顺序输入，不批准库外路径或覆盖竞争。绑定从有效路径取文件名及实际字节大小；上传记录写入后的文件名及文件字节数。
3. 文件准备完成后，在数据库事务内清除旧默认并新增可见、默认、Pending版本，成功提交后才返回新记录。创建/更新时间为UTC，DownloadCount初始0。文件写入早于数据库事务，落库失败遗留文件及重试去重仍属B04，不能声称文件/数据库整体回滚。上传失败返回HTTP400；原路径绑定异常当前也返回HTTP400，错误文案来自实际响应。
4. 资料编辑先定位版本，缺失404；存在只改版本号、日志和UTC更新时间，文件信息/归属/默认/哈希不变。设默认先查存在，再查可见，再对已默认请求直接成功；需要切换时按数据库事务清旧默认并设目标。显隐和删除记录的数据库变更按REQ-版本管理-001-003执行；缺失目标返回404。
5. 公共下载必须同时满足父软件发布状态、软件库边界及本条版本资格。现有下载代码依次检查版本存在、归属、可见性和物理文件存在；父软件发布及库边界检查仍为B01/B03目标差距，本规格不预定其修复判断顺序。满足条件返回`application/octet-stream`、安装包文件名及文件流，Range由文件响应处理；表中404仅适用于明确列出的拒绝。文件被并行移除、流传输中断、重复下载/Range的计数语义及非法Range错误码不在已有目标中补定。

顺序重复设当前默认不产生第二默认；其他重复上传/绑定和并发编辑未获得幂等承诺。页面下载后会乐观增加显示计数，服务也有异步计数逻辑，但它们不证明传输完成或计数准确，仍按B04待办处理。

## 必要技术设计与各端契约

单软件默认切换的数据更新必须在同一数据库事务中进行；迁移定义包含每软件默认唯一的部分索引。部署数据库是否应用该迁移必须单独核对，不能以源文件代替实际schema证据。

契约源为`Controllers/Admin/AdminVersionsController.cs`、`AdminFilesController.cs`、公共`DownloadController.cs`和版本DTO；消费者为管理/公共`SoftwareDetail.vue`。页面删除固定请求physicalDelete=true，而API默认false；API成功仅删记录时保留物理文件的事实为R30，页面“仅删记录”入口仍是旧目标待办。显隐/删除后页面默认标记未刷新属于B07，不能用过期展示覆盖数据库目标。

## 验收条件

### AC-版本管理-001-001（验证 REQ-版本管理-001-001）
前提：有效软件已有关联版本及默认版，安装包在库内。
操作：分别成功上传及绑定新版本，再编辑其日志；另向不存在软件或用空文件上传。
结果：新版本可见、Pending且成为唯一默认，旧默认取消；资料更新不改变文件归属；两种无效上传均拒绝。

### AC-版本管理-001-002（验证 REQ-版本管理-001-002）
前提：一个隐藏版和两个可见版，其中一版为默认。
操作：设隐藏版为默认；重复设当前默认；改设另一可见版。
结果：第一项拒绝且不切换默认，第二项保持，第三项只有目标为默认。

### AC-版本管理-001-003（验证 REQ-版本管理-001-003）
前提：按表中各事件分别准备创建时间不同的版本集合。
操作：隐藏、显示或成功删除记录，包含只剩隐藏版本和没有剩余版本的分支。
结果：每项默认结果与表一致，最多一个默认且必须可见；无可见版本无默认。

### AC-版本管理-001-004（验证 REQ-版本管理-001-004）
前提：公开可访问软件有一个较早默认版、多个新可见版和隐藏版。
操作：分别查询后台与公共列表，点击下载最新版；再在无版本软件操作。
结果：后台含隐藏版、公共不含；默认优先，下载目标为默认；无版本不发起版本下载。

### AC-版本管理-001-005（验证 REQ-版本管理-001-005）
前提：已发布软件有库内可读安装包。
操作：完整下载及Range下载；再分别使用不存在版本、错误父ID、隐藏版和缺失文件。
结果：前两项返回准确内容及相应区间（有效范围206）；后四项404且无安装包内容。

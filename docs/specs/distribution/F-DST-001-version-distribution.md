# F-DST-001 版本、文件扫描、哈希与下载分发

状态：approved
确认状态：本阶段正式确认（代码优先基线）

## 目标与范围

定义软件包从 NAS/上传进入数据库、扫描孤儿文件、绑定版本、计算哈希、设置默认、可见性、删除、下载计数和恢复的完整生命周期。SMB 是系统外的文件复制步骤；本 Spec 只定义系统对其结果的处理。

## 基线决策与证据

本 Spec 采用“代码优先的正式现状基线”。用户已明确确认：本阶段未单独确认的行为，以当前代码、当前前端消费者、数据模型、Docker 输入和发布脚本实际表达的行为为准。该确认包括当前实现中已经存在的限制和缺陷；它们不会被伪装成已修复功能。

本文件中的 REQ/AC 用于记录本能力的稳定边界和可追溯验收口径；与当前实现存在差异的历史目标，按下方“已知问题备注”处理，暂不作为本阶段已完成能力。后续要改变行为，必须建立新的 Change，更新 REQ/AC、契约、消费者和验证证据。

## 规范性需求（当前正式基线）

### REQ-DST-001-001
当管理员为存在的软件绑定实际文件时，系统必须保存软件 ID、版本号、日志、文件名、规范化路径和真实字节大小，并创建 Pending、可见且默认的版本记录；文件或软件不存在时不创建记录。
来源：PRD:50–54；VersionService.CreateAsync；取舍 D4

### REQ-DST-001-002
当管理员扫描配置软件根目录或其子目录时，系统必须递归列出存在且未被版本记录绑定的文件及名称、路径、字节大小；路径规范化后比较，越界或不存在目录返回明确错误，不创建任意请求目录。
来源：PRD:46–47；FileService.ScanUnboundFilesAsync

### REQ-DST-001-003
当管理员在扫描结果选择入库时，页面必须打开绑定表单，锁定文件名/大小/路径，允许按名称选择归属软件、填写版本号与日志；成功后关闭表单并移除该孤儿项，失败时保留输入供重试。
来源：PRD:48、65；UIUX:79–88；当前 Files.vue 为占位

### REQ-DST-001-004
当后台处理 Pending 哈希作业时，系统必须流式读取文件并推进为 Computing；成功保存 64 位小写 SHA-256 和 Done，缺失文件或读取异常进入 Failed 且校验码为空，内部原因通过版本 ID 关联日志。
来源：PRD:54；HashComputeService

### REQ-DST-001-005
当访客下载版本时，系统必须执行 REQ-CAT-001-007 的父软件与可见性限制，验证版本归属及实际文件存在，再返回带原记录 FileName 的二进制下载和合法 Range 响应；不满足条件返回 404，不增加计数。
来源：PRD:29、43；DownloadController；现状父状态缺口

### REQ-DST-001-006
当管理员指定默认版本时，系统必须只允许可见版本成为默认，同一软件最多一个默认；重复指定同项不产生额外状态变化，隐藏目标返回 400。
来源：当前 SetDefaultAsync 与事务

### REQ-DST-001-007
当默认版本被隐藏或删除时，系统必须清除该默认并提升创建日期最新的剩余可见版本；没有剩余项则无默认；恢复可见项时只在当前无可见默认的情况下设为默认。
来源：当前默认替代调用链；取舍 D4

### REQ-DST-001-008
当管理员删除版本时，界面必须提供“仅记录”和“记录及文件”两种明确选择；仅记录保留物理文件，彻底删除必须确认文件处理成功后再移除记录，文件已缺失视为无须再删，物理删除失败保留记录并报错。
来源：PRD:57–59；API physicalDelete / 当前 UI 固定 true

### REQ-DST-001-009
当管理员创建或编辑版本元数据时，系统必须拒绝空白版本号，允许空更新日志；编辑只改变版本号、日志和 UpdatedAt，不修改物理文件、CreatedAt、下载计数或哈希；版本号不作为全局唯一键。
来源：VersionCreate/UpdateRequest；当前版本编辑

### REQ-DST-001-010
当管理员选择或拖拽上传软件包时，页面必须展示真实传输进度和上传结果；失败允许重试。若新软件档案已创建而包上传失败，页面必须保留该软件 ID 并告知部分成功，重试不重复创建软件。
来源：当前拖拽/进度/创建后上传流程

### REQ-DST-001-011
当记录或显示文件大小时，系统必须以 64 位字节数持久化真实大小，允许零字节文件；页面按 1024 换算并使用 KiB/MiB/GiB 单位，不因超过 2 GiB 发生整数溢出。
来源：PRD:53；FileSize long；大文件定位

### REQ-DST-001-012
当服务端接受一次有效 GET 下载（含 Range）并准备文件响应时，系统必须在同一数据库事务中原子增加版本 DownloadCount 与软件 TotalDownloads；拒绝请求不计数，客户端随后取消不撤销，重复有效请求分别计数。统计的是请求，不宣称完整传输次数。
来源：PRD:29；当前未等待计数；取舍 D5

### REQ-DST-001-013
当扫描、绑定、上传、读取或删除软件文件时，系统必须将实际路径限制在配置存储根目录内，拒绝目录穿越、文件名携带目录以及经链接逃逸的路径；公开响应仅使用下载引用，不暴露物理路径。
来源：当前任意路径输入与 FileName 拼接；路径边界建议

### REQ-DST-001-014
当上传名称与已有文件冲突或文件写入后数据库保存失败时，系统必须防止覆盖原文件和原版本；新文件使用唯一存储名，保存失败清理本次新文件并报告失败，不误删他人文件。
来源：UploadAsync 时间戳重名与文件/数据库非原子边界

### REQ-DST-001-015
当单实例哈希服务从中断恢复时，系统必须把遗留 Computing 作业重新排队为 Pending；正常停机取消不写入虚假的 Done。失败后由管理员明确触发重新计算，重算前清空旧摘要并排队。
来源：当前仅查询 Pending 的恢复缺口

### REQ-DST-001-016
当管理员在软件编辑页使用手动路径绑定时，系统必须沿用 REQ-DST-001-001、REQ-DST-001-009、REQ-DST-001-013 的同一验证和版本创建规则；该入口与扫描结果绑定分别保留，不以一条路径替代另一条的完成判断。
来源：后台 SoftwareDetail.vue:609–620

### REQ-DST-001-017
当查询公开或管理版本列表时，系统必须按 IsDefault 降序、CreatedAt 降序、Id 升序稳定排列；管理列表包含隐藏项，公开列表仍执行 REQ-CAT-001-007。
来源：当前默认项优先；PRD 时间倒序冲突；取舍 D4

### REQ-DST-001-018
当管理员通过 NAS 工作流发布版本时，外部 SMB 先完成文件复制且不原位覆盖已绑定文件；系统随后支持扫描→绑定→哈希状态展示→按软件/版本状态公开下载的完整链路，未完成摘要时真实展示 Pending/Computing。
来源：PRD:61–67；SMB 为系统外步骤

## 质量与边界

物理路径必须受配置根目录约束；数据库记录、文件操作和公开响应的失败边界必须可诊断；大文件按流处理，不把文件内容加载进内存。计数、哈希、默认项和删除需覆盖并发/中断/恢复边界。

## 各端和契约关系

接口和 DTO 的当前入口见 [HTTP 契约参考](../../contracts/http-api.md)。后端控制器、请求/响应 DTO、EF 模型和迁移是当前实现事实的权威来源；本 Spec 的 REQ/AC 是目标行为来源。涉及跨端的需求必须同时核对 API、消费者、持久化和错误处理。

## 必要技术说明

`VersionService` 保存版本元数据并处理默认项、可见性和删除；`FileService` 扫描物理目录；`HashComputeService` 是后台宿主服务；下载控制器返回范围文件。所有入口共享路径规范化、父软件公开状态、可见性和文件存在校验，避免扫描入口与手动绑定入口出现不同安全规则。

## 验收场景

### AC-DST-001-001（验证 REQ-DST-001-001）
Given 有效软件、根目录内文件；另有不存在文件或软件 ID
When 分别提交绑定
Then 有效项保存真实大小并排队；无效项返回明确错误且无新版本/默认项变化

### AC-DST-001-002（验证 REQ-DST-001-002）
Given 根目录内有已绑定文件、深层未绑定文件和相同路径的不同斜杠表示
When 扫描根目录及不存在/越界目录
Then 只列深层未绑定项；不存在/越界请求报错，不创建目录、不泄露根目录外文件

### AC-DST-001-003（验证 REQ-DST-001-003）
Given 扫描结果含一份孤儿文件
When 打开入库，选择软件并保存，再模拟保存失败
Then 成功项被绑定并从列表移除；失败保留原项和表单，取消不写数据

### AC-DST-001-004（验证 REQ-DST-001-004）
Given 一份可读文件和一份读取失败文件对应 Pending 版本
When 处理作业
Then 可读项经过 Computing 到 Done 且摘要等于独立计算；失败项为 Failed，无伪造摘要或公开异常路径

### AC-DST-001-005（验证 REQ-DST-001-005）
Given 已发布可见文件，及隐藏/父下架/ID 不匹配/物理缺失案例
When 请求完整下载、有效 Range、无效案例
Then 完整内容及名称正确，Range 返回对应字节；无效案例 404，无计数变化

### AC-DST-001-006（验证 REQ-DST-001-006）
Given 同一软件有两份可见版本与一份隐藏版本
When 设置第二项默认，重复设置，再指定隐藏项
Then 最多第二项为默认；重复操作不改变其他数据；隐藏请求 400 且原默认保留

### AC-DST-001-007（验证 REQ-DST-001-007）
Given 默认项和两份不同日期可见项
When 隐藏/删除默认项，然后恢复隐藏项
Then 最新剩余项被提升；已存在默认时恢复项不抢占；全部隐藏时无默认

### AC-DST-001-008（验证 REQ-DST-001-008）
Given 根目录内一份已绑定文件，另有权限拒绝删除的文件
When 分别仅删记录、彻底删除和删除失败
Then 仅删后文件保留并可重新扫描；彻底删除移除两者；失败保留记录与默认状态并显示错误

### AC-DST-001-009（验证 REQ-DST-001-009）
Given 已存在带摘要和计数的版本
When 提交空白版本号，再修改版本号和日志
Then 空白被拒绝；合法修改保存，文件/创建时间/计数/摘要保持原值

### AC-DST-001-010（验证 REQ-DST-001-010）
Given 新软件创建成功，首次上传中断
When 观察进度、失败提示并重试
Then 进度对应传输，错误不伪报全部成功；重试复用软件 ID，仅成功上传时出现新版本

### AC-DST-001-011（验证 REQ-DST-001-011）
Given 0 字节、1024 字节和超过 2 GiB 文件
When 绑定并显示大小
Then 数据库字节数准确，显示为 0 B、1 KiB 及正确 GiB 值，无截断或负数

### AC-DST-001-012（验证 REQ-DST-001-012）
Given 软件和版本计数都为 0
When 并发执行 20 次有效下载和 3 次被拒绝请求
Then 两种计数各为 20；拒绝不计数；有效 Range/重试各计一次，无并发丢失

### AC-DST-001-013（验证 REQ-DST-001-013）
Given 根内文件、../ 越界路径、链接到根外的文件以及含目录的上传文件名
When 逐项扫描/绑定/上传/删除
Then 合法根内操作有效；其余被拒绝，根外文件未读写，公开响应无物理路径

### AC-DST-001-014（验证 REQ-DST-001-014）
Given 已有同名包，另模拟数据库保存失败
When 同时上传同名包，再执行失败案例
Then 原包摘要不变；成功项存储名各不相同；失败项无新版本及本次残留文件

### AC-DST-001-015（验证 REQ-DST-001-015）
Given 数据库有遗留 Computing 和 Failed 版本
When 重启单实例服务，对 Failed 项请求重算
Then 遗留项重新计算；明确重算项进入 Pending 并最终 Done/Failed，无永远停在 Computing 的已知作业

### AC-DST-001-016（验证 REQ-DST-001-016）
Given 存在软件与合法包路径
When 在编辑页绑定并提交空版本号/越界路径
Then 合法操作创建版本；非法操作被拒绝，两个 UI 入口都指向相同验证规则

### AC-DST-001-017（验证 REQ-DST-001-017）
Given 默认旧版本和两个普通新版本，其中一项隐藏
When 查询公开与管理列表
Then 默认项优先，其余按日期；同日顺序稳定；隐藏项只在管理列表出现

### AC-DST-001-018（验证 REQ-DST-001-018）
Given 隔离软件根目录内完成复制的安装包和存在的软件
When 扫描、绑定、等待哈希，再访问公开详情并下载
Then 孤儿项消失，大小和摘要准确，公开可见性正确，下载内容与原包一致；SMB 传输速度不被冒充为 Web 性能证据

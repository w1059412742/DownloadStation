## 目标与范围

在单实例服务持续运行、库内文件在计算期间稳定的条件下，对Pending版本流式计算SHA256。不承诺崩溃后的Computing恢复、Failed重试、多实例任务抢占、停机中断和并行删除一致性；这些保留B05，不作为已批准现状。

## 功能规则

### REQ-文件校验-001-001：顺序计算完整摘要
服务运行且有Pending版本时，必须逐次选创建时间最早的Pending，先持久化Computing及UTC更新时间，再读取文件计算SHA256；成功后必须保存完整64字符小写十六进制摘要、Done及UTC更新时间。对相同字节内容必须得到相同SHA256，文件不因计算改变。创建时间并列时不承诺额外ID顺序。

### REQ-文件校验-001-002：计算失败与轮询
所选版本的文件不存在或本次读取/计算异常时，必须将其记为Failed并继续后续循环；无Pending时必须等待5秒后继续查找，外层循环异常后等待10秒再继续。不把轮询间隔解释为完成时限。

## 循环与异常处理逻辑

每轮建立独立依赖注入作用域和数据库上下文，取最早Pending的一条；不一次并行取多条，也不自动重选Computing/Done/Failed。选择到记录后先保存Computing，再检查文件存在；不存在则标Failed，存在则以只读流计算。计算/读取异常在该条任务内转Failed，随后保存最终状态并进入下一轮。没有任务等待5秒；作用域、查询或持久化等外层异常记录日志并等待10秒，不保证该异常中的最终状态已保存。

HashSHA256在Done时才是完整摘要；失败时现字段还会承载说明文本，不作为64位摘要使用，前端的截断展示由软件浏览规格定义。任务计算不修改安装包或默认/可见属性；可见性和发布状态不影响已有Pending任务被选择，但所有安装包读取仍须遵守软件库目标边界。中断/取消后遗留Computing、Failed重试和多实例抢占仍是B05；不将日志中的“锁定”当成已存在数据库抢占锁。

## 状态与契约

正常路径为Pending → Computing → Done，缺文件或计算异常为Computing → Failed。任务由`Program.cs`注册，代码权威源为`BackgroundServices/HashComputeService.cs`，结果由`VersionResponse`提供给前后台详情。展示含义引用访客规格，不是恶意软件检测结果。

## 验收条件

### AC-文件校验-001-001（验证 REQ-文件校验-001-001）
前提：单实例持续运行，有两个创建时间不同的Pending，文件稳定可读。
操作：运行计算任务并读取状态与摘要。
结果：选择次序按最早创建，持久化Computing后得到Done，摘要等于独立SHA256计算，文件字节不变。

### AC-文件校验-001-002（验证 REQ-文件校验-001-002）
前提：Pending指向缺失文件或读取故障文件，其后有可读任务。
操作：运行循环，另观察空队列及外层异常分支。
结果：失败任务为Failed，后续任务仍被处理；空队列及外层异常分别按5秒和10秒间隔再查，不承诺本次范围外自动重试Failed。

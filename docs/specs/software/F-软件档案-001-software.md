维护软件基本信息、发布状态、图标及HTML介绍。软件和文件的破坏性删除、HTML安全策略、非法输入及同名竞争的现状不在采用范围，见B04/B06/B07；独立截图相册与灯箱保留未来目标。有效输入指页面要求的非空名称、已存在平台和有效可选关联，非任意HTTP载荷。

## 功能规则

### REQ-软件档案-001-001：保存档案及关联
管理员保存有效软件档案时，系统必须保存名称、简介、HTML介绍、图标路径、官网、一个可选分类、一个可选平台及多个标签。创建未指定状态时必须为Published；更新必须替换标签集合而不是仅追加，空集合清除关联。空白分类/平台引用必须存为无关联；字典删除导致的平台空值不改变软件身份。

### REQ-软件档案-001-002：后台检索与发布状态
后台列表必须包括Draft和Published，支持分类、平台、标签、关键词联合过滤，标签条件为软件含指定标签；分类/平台/关键词、排序和分页采用[访客检索 REQ-软件浏览-001-001/002](../catalog/F-软件浏览-001-browse.md)的共同语义，排序参数大小写归一化及回退分支统一引用REQ-软件浏览-001-002。后台不受公共接口“无标签过滤”限制，后台API默认每页20条。后台详情和更新/状态切换目标不存在时必须返回不存在；有效状态切换必须持久化Draft=0或Published=1。

### REQ-软件档案-001-003：编辑校验与富文本
软件编辑页必须在名称或平台缺失时阻止保存；保存前必须尝试同平台同名预查并在命中时阻止该次保存，编辑时排除自身。预查不是数据库唯一约束，不能据此承诺并发去重。富文本编辑器必须输出HTML并支持将上传图片插入介绍；图标与介绍图片复用图片上传能力。

### REQ-软件档案-001-004：图片上传
对于已认证、非空且在请求10 MiB（10,485,760字节）限制内的图片上传，系统必须按服务端本地日期`yyyyMMdd`目录和无连字符GUID文件名保存、保留原扩展名，并返回`/uploads/images/...` URL；空文件必须拒绝。此为整个HTTP请求限制，含表单开销，不表示恰好10 MiB的文件必然可上传。图片存放于独立UploadBasePath，不是安装包软件库。采用HTML和图片能力不允许将未验证的内容安全性写为已满足。

### REQ-软件档案-001-005：新建软件与版本的部分失败
新建软件并同时添加版本时，编辑页必须先保存软件，再上传或绑定文件；若第二步失败，必须保留已创建的软件并提示软件已保存但版本步骤失败，不得将两步表现为整体成功。

## 保存流程与失败边界

1. 编辑页以`/admin/softwares/new`新建，以实际ID编辑；加载分类、平台、标签字典后读取已存在软件和版本。档案字段为名称、简介、介绍、图标URL、官网URL、分类ID、平台ID、发布状态、标签ID集合；简介/介绍/图标/官网可为空，分类可不选，页面保存要求名称和平台，API数据模型则允许平台为空。不得把页面必选当成所有API已有同一拒绝规则。
2. 保存先检查名称/平台，新建且已选上传文件时还检查版本号，然后尝试同平台同名预查，命中即停止。预查请求失败时现代码会继续保存，是B07校验缺口，不批准为可靠去重策略；本条不把客户端预查替代数据库约束。
3. 后端新建保存一个软件及有效标签关联；编辑先查目标，存在才更新字段、加载旧标签、清空并重新关联给定集合，一次保存使该档案及标签变更一起落库。null/空标签集合清除旧标签；仅适用有效关联ID，不把忽略不存在标签的现状扩成新的业务许可。档案时间使用UTC；默认Published源于创建DTO，而非省略状态即可改变已有软件状态。
4. 新建档案返回ID后才执行所选文件步骤；没有选文件/手工路径时只保存档案。第二步成功才提示对应上传/绑定成功，失败必须提示部分成功；之后返回后台软件列表。编辑现有档案保存成功也返回列表；档案保存失败显示响应message或操作失败，不启动首个版本步骤。
5. 图标上传成功后才将URL写入表单；介绍图片由富文本编辑器上传成功后插入HTML。图片上传不等于档案已保存；后续取消/保存失败的孤立图片清理及不可信内容处理仍未获正确策略，保留B04/B06，不推定已自动回收或清理。

图片写入失败时当前接口以失败响应返回，页面提示上传失败；文件写入与档案保存无整体事务。软件删除、文件异常、同名并发及非法载荷的正确处理仍需后续安排，不将这些范围标为可直接据本规格重写。

## 各端行为与契约

契约源为`Controllers/Admin/AdminSoftwaresController.cs`、软件请求/响应DTO和`SoftwareService`；消费者为`views/admin/Softwares.vue`、`views/admin/SoftwareDetail.vue`、`components/common/RichEditor.vue`及公共详情。图片访问由`Program.cs`静态文件映射提供。结构字段留在DTO，不另抄一份API规范。

## 验收条件

### AC-软件档案-001-001（验证 REQ-软件档案-001-001）
前提：有效分类、平台和两个标签存在。
操作：创建含HTML的软件；更新时更换标签集合，再清空集合。
结果：档案字段和单平台保存，默认Published；更新只保留新标签，清空后无标签关联。

### AC-软件档案-001-002（验证 REQ-软件档案-001-002）
前提：有Draft和Published软件以及有效标签。
操作：后台API联合筛选，使用AC-软件浏览-001-002的排序参数组查询；切换有效软件状态，读取和更新不存在的软件。
结果：后台可查两类状态，筛选共同成立；排序参数各分支结果与REQ-软件浏览-001-002相同；状态持久化，不存在目标返回不存在。本AC不表示后台页面新增排序控件。

### AC-软件档案-001-003（验证 REQ-软件档案-001-003）
前提：软件编辑页及同平台同名记录存在。
操作：缺名称/平台保存、预查命中后保存；编辑原记录且排除自身；插入已上传介绍图片。
结果：前两种保存被阻止，自身不构成重名；编辑器输出包含图片URL的HTML。

### AC-软件档案-001-004（验证 REQ-软件档案-001-004）
前提：隔离图片目录可写，管理员已登录。
操作：上传非空小图片及空文件。
结果：前者存为日期/GUID路径并返回可访问URL；后者拒绝，不产生图片。

### AC-软件档案-001-005（验证 REQ-软件档案-001-005）
前提：新软件的档案保存成功，随后文件步骤失败。
操作：提交软件与首个版本。
结果：软件仍可在后台查询，页面明确提示版本失败，不宣称版本已成功添加。
